## Найденные проблемы

### Критично — JavaScript-песочница выполняет код в основном окне
В `js/app.js` используется `new Function(...)` в контексте основной страницы. Переданный объект `console` подменяет только console, но не изолирует `window`, `document`, `localStorage`, навигацию и другие API страницы. Это позволяет учебному коду затронуть само приложение и сохранённые данные. До исправления не следует запускать неизвестный код.

**Решение:** перенести выполнение в отдельный sandboxed iframe без `allow-same-origin`, ограничить CSP, передавать только сообщения о выводе и ошибках; предусмотреть перезапуск iframe при зависании.

### Высокий приоритет — ненадёжная загрузка прогресса
`JSON.parse(localStorage...)` обёрнут в try/catch, но корректный JSON любого типа (например, `null`, объект или строка) проходит парсер и затем может сломать `done.includes` / `done.push`.

**Решение:** проверять Array, фильтровать только известные ID уроков, обрабатывать недоступность localStorage.

### Средний приоритет — неполная валидация прогресса
Сохранённые ID не сверяются с текущим каталогом уроков. Удалённые или повторяющиеся ID могут искажать счётчик и процент.

**Решение:** нормализовать список через Set и разрешённые ID; процент ограничивать диапазоном 0–100.

### Средний приоритет — слишком мало проверок знаний
Есть один тестовый вопрос, который не связан с прогрессом курса и не проверяет практическое выполнение.

**Решение:** добавить наборы вопросов и проверяемые практические задачи по каждому модулю после стабилизации основы.

### Низкий приоритет — доступность и устойчивость интерфейса
Нужны проверки клавиатурной навигации, фокуса, длинных строк в редакторе, состояния меню и поведения при отключённом JavaScript.

Первоначальные критические проблемы с запуском JavaScript и валидацией прогресса устранены. Текущая версия расширена и прошла статические проверки и GitHub Actions.

- Экзамен с 10 случайными вопросами из каталога уроков.
- 10 практических задач по HTML, CSS, JavaScript и Python с проверкой критериев.
- Отдельные песочницы JavaScript и веб-страницы; sandboxed iframe без `allow-same-origin`.

- Автосохранение черновиков, экспорт/импорт прогресса и проверка размера/содержимого резервной копии.

- GitHub Actions: синтаксис JavaScript, структура уроков, уникальность ID, соответствие селекторов, контрольные решения задач, песочницы и PWA-ресурсы.

### Результаты автоматической проверки
- Синтаксис `js/app.js`, `js/lessons.js`, `sw.js` и встроенного JS Python-песочницы — без ошибок.
- 32 урока с уникальными ID и корректными вопросами.
- 10 практических заданий; все демонстрационные решения проходят каждый критерий.
- HTML ID уникальны; отсутствующих селекторов приложения не обнаружено.
- Последний запуск GitHub Actions для рабочей ветки прошёл проверки шагов JavaScript и платформы успешно.

### Ограничения и незавершённая проверка
- Skulpt — учебная реализация Python, не полный CPython; поддержка стандартной библиотеки ограничена. CDN требуется для первой загрузки и для запуска Python после очистки кэша.
- Офлайн-кэш хранит локальные файлы приложения, но не загружает Skulpt в кэш; Python офлайн недоступен.
- Service Worker требует HTTPS или localhost; при открытии файлов напрямую в TrebEdit он не работает.
- Не проводились физические испытания на телефоне пользователя, браузерные E2E-тесты, Lighthouse и ручная проверка установки PWA.
- Статические тесты не заменяют тестирование реального исполнения Python и JavaScript в мобильных браузерах.

- Закладки на отдельные уроки с быстрым переходом к материалу.

Данные остаются в localStorage браузера и не отправляются на сервер. Для переноса между устройствами нужно вручную экспортировать и импортировать JSON-резервную копию. GitHub Actions проверяет структуру и интеграционные маркеры, но не заменяет ручную проверку пользовательских сценариев в браузере.


## Этап 4 — проверяемые мини-проекты

- В мастерской проектов добавлен список критериев для каждого из трёх стартовых проектов.
- Проверка анализирует HTML/CSS как текст и показывает отдельно выполненные и невыполненные пункты; код предпросмотра не исполняется проверяющим механизмом.
- Награда 50 XP и отметка завершения выдаются только после успешного прохождения всех критериев, повторное прохождение не начисляет XP повторно.
- При выборе другого проекта список результатов очищается; статус и прогресс обновляются в кабинете.
- Автоматические тесты проверяют наличие интерфейса, функцию проверки и то, что стартовый код каждого проекта проходит все свои критерии.
- GitHub Actions для коммита `f93b4a6` завершился успешно.

Проверка статическая и учебная: она проверяет наличие ожидаемых конструкций, а не семантическую корректность или визуальное качество произвольного сайта. Это не замена браузерным тестам и ручной оценке.


## Этап 5 — экзамены по направлениям и сложности

- Добавлены отдельные экзамены по HTML/CSS, JavaScript и Python, а также смешанный экзамен.
- Доступен фильтр уровня: «Начальный», «Начальный+» или все уровни.
- Вопросы перемешиваются алгоритмом Fisher–Yates; число вопросов ограничивается размером выбранного банка (максимум 10).
- После завершения показываются процент и число правильных ответов.
- В localStorage отдельно сохраняются лучший процент, последний результат и количество попыток для каждой комбинации направления и уровня.
- Добавлен экран истории результатов; экзамены намеренно не начисляют XP.
- Автотесты проверяют наличие контролов, хранилища результатов и достаточного числа вопросов в каждом направлении.

Ограничение: уровень «Начальный+» — это текущая следующая ступень курса, а не полноценный продвинутый профессиональный экзамен. Вопросы пока основаны на проверочных вопросах уроков; отдельные ситуационные и практические экзаменационные задачи остаются следующим улучшением.


## Этап 6 — разбор ошибок и адресная повторная практика

- Экзамен сохраняет список неверно отвеченных вопросов в памяти текущей попытки.
- После завершения показывает правильный ответ и объяснение для каждого пропущенного вопроса.
- Добавлена возможность повторить только вопросы, на которые пользователь ответил неверно.
- При идеальном результате вместо пустого блока показывается отдельное сообщение.
- Разбор строится через DOM API и `textContent`; строки вопроса и пояснения не вставляются как HTML.
- Автотесты проверяют наличие сбора ошибок, интерфейса разбора и адресного повтора.

Ограничение: ошибки хранятся только до следующей попытки и не образуют долговременную аналитику по темам. Для настоящего анализа пробелов знаний понадобится расширить модель вопросов тегами тем и хранить историю отдельных ответов.


## Этап 7 — мобильная рабочая область веб-лаборатории

- Для узких экранов добавлены вкладки HTML, CSS, JavaScript и предпросмотра; одновременно показывается только выбранная рабочая панель.
- Для десктопной ширины сохранено одновременное отображение редакторов и предпросмотра.
- Добавлен контролируемый размер шрифта 11–20 px.
- Tab вставляет два пробела, Ctrl/Cmd+Enter запускает предпросмотр.
- Автотесты проверяют наличие вкладок, управления размером и клавиатурных обработчиков.

Ограничение: автоматические проверки подтверждают структуру и обработчики, но не заменяют проверку реальной клавиатуры Android, экранной клавиатуры и браузерной геометрии на физическом устройстве. Мобильное переключение использует CSS ` :has()` селектор; для очень старых браузеров может потребоваться упрощённый режим без вкладочного скрытия.

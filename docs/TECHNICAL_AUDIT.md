## Найденные проблемы

### Критично — JavaScript-песочница выполняет код в основном окне
В `js/app.js` используется `new Function(...)` в контексте основной страницы. Переданный объект `console` подменяет только console, но не изолирует `window`, `document`, `localStorage`, навигацию и другие API страницы. Это позволяет учебному коду затронуть само приложение и сохранённые данные. До исправления не следует запускать неизвестный код.

**Решение:** перенести выполнение в отдельный sandboxed iframe без `allow-same-origin`, ограничить CSP, передавать только сообщения о выводе и ошибках; предусмотреть перезапуск iframe при зависании.

### Высокий приоритет — ненадёжная загрузка прогресса
`JSON.parse(localStorage...)` обёрнут в try/catch, но корректный JSON любого типа (например, `null`, объект или строка) проходит парсер и затем может сломать `done.includes` / `done.push`.

**Решение:** проверять Array, фильтровать только известные ID уроков, обрабатывать недоступность localStorage.

### Средний приоритет — неполная валидация прогресса
Сохранённые ID не сверяются с текущим каталогом уроков. Удалённые или повторяющиеся ID могут искажать счётчик и процент.

**Решение:** нормализовать список через Set и разрешённые ID; процент ограничивать диапазоном 0–100.

### Средний приоритет — слишком мало проверок знаний
Есть один тестовый вопрос, который не связан с прогрессом курса и не проверяет практическое выполнение.

**Решение:** добавить наборы вопросов и проверяемые практические задачи по каждому модулю после стабилизации основы.

### Низкий приоритет — доступность и устойчивость интерфейса
Нужны проверки клавиатурной навигации, фокуса, длинных строк в редакторе, состояния меню и поведения при отключённом JavaScript.

## Этап 11 — надёжность JavaScript и Python-песочниц (A1)

Дата: 2026-11-06  
Ветка: `audit/foundation-hardening`

### JavaScript
- Синхронный пользовательский код больше не выполняется в основном потоке iframe: он запускается в отдельном Blob Worker, созданном изолированной страницей `sandbox.html`.
- Родительский интерфейс может остановить Worker вручную или завершить его после 1,8 секунды; после тайм-аута iframe пересоздаётся.
- Добавлены обработчики ошибок Worker и проверки ID запросов.
- Ограничения: код — 100 000 символов, вывод — 50 000 символов, текст ошибки — 4 000 символов.
- CSP включает `worker-src blob:`, `script-src ... blob:` и `connect-src 'none'`; iframe по-прежнему использует `sandbox="allow-scripts"` без `allow-same-origin`.

### Python
- Ограничены размер входного кода (100 000 символов) и вывод (50 000 символов).
- Сохранён лимит Skulpt `execLimit: 3000`; родительский тайм-аут — 7 секунд с перезапуском iframe.
- Добавлена явная кнопка повторной загрузки среды, в том числе после ошибки CDN.
- Ошибки и ответы проверяются по источнику iframe и ID активного запуска.

### Проверки и ограничения
- Статические CI-проверки проверяют наличие Worker, CSP, ограничений, кнопки остановки, retry и синтаксис встроенного Worker-кода через Node VM.
- Эти проверки не доказывают фактическое поведение Chromium/WebKit и не заменяют Playwright E2E.
- До A2 необходимо подтвердить в реальном браузере: создание Blob Worker из opaque-origin iframe, завершение бесконечного цикла без блокировки интерфейса, обработку CSP/network и корректный повторный запуск.
- Физическое тестирование Android/TrebEdit не проводилось.

## Этап A5 — версионирование данных, резервные копии и PWA (выполнен)

### Хранение и миграции
- Добавлена схема `cc_storage_schema`, текущая версия — 2. Старые профили без ключа схемы мигрируются последовательно при запуске.
- Миграция очищает неизвестные ID и дубликаты, ограничивает размер заметок/черновиков, нормализует отметки проектов и экзаменационную статистику.
- Миграция записывает новую версию схемы последней. Если запись не удалась, версия не продвигается; повторный запуск может безопасно повторить миграцию.
- Данные остаются локальными в localStorage. Синхронизация между браузерами/устройствами не реализована.

### Резервные копии
- Новый экспорт использует backup version 2 и содержит schemaVersion.
- Импорт сохраняет обратную совместимость с version 1, объединяет существующие и импортированные значения и отбрасывает неизвестные ID/невалидные формы.
- Пакет записи сохраняет прежние значения и пытается откатить их при ошибке записи; quota error больше не маскируется успешным сообщением.
- Ограничение файла импорта остаётся 2 MiB; это защита от чрезмерного ввода, не гарантия доступного места в браузере.

### Service Worker и PWA
- Shell cache обновлён до `codecraft-shell-v2`, runtime cache — до `codecraft-runtime-v2`; старые cache names с префиксом `codecraft-` удаляются при activate.
- Runtime cache ограничен 80 записями. Навигация использует network-first с fallback на сохранённый `index.html`; локальные ресурсы используют cache-first.
- Ошибка записи в Cache Storage не должна блокировать сетевой ответ.
- Manifest содержит app id, scope/start_url, категории и display override. Иконка использует текущий SVG asset.
- Python/Skulpt намеренно не включён в precache: первая загрузка и выполнение Python требуют CDN-доступа.

### Проверки и статус
- В A5 добавлены E2E сценарии для legacy migration, quota rollback и offline shell.
- Эти сценарии считаются выполненными только после зелёного GitHub Actions run на commit, содержащем их.
- Установка на реальное Android-устройство, Android WebView/TrebEdit, проверка install prompt и поведение при нехватке дискового пространства ещё не подтверждены.
- A5 остаётся в работе до завершения CI и исправления всех обнаруженных регрессий.

## Этап A7 — навигация по последовательности уроков

- `showLesson(index)` строит последовательность только из уроков с тем же `course`, вычисляет позицию текущего урока и выводит локальный номер курса.
- На границах курса кнопки перехода отключаются; обработчики дополнительно проверяют границы до вызова `showLesson`.
- Каталог помечает активный урок атрибутом `aria-current="step"`.
- После перехода фокус восстанавливается на доступной кнопке нового урока; при достижении первого урока, где «Предыдущий» отключён, фокус переносится на «Следующий».
- Мобильная компоновка переносит счётчик между кнопками; тяжёлые библиотеки не добавлены.
- E2E покрывает HTML/CSS и JavaScript последовательности, границы и фокус.


## Этап A8 — клавиатурная эргономика учебных редакторов

- Единый обработчик подключён к семи полям: JavaScript, HTML, CSS, веб-JavaScript, практическое задание, мини-проект и Python.
- Для выделенного блока Tab добавляет два пробела в начало каждой строки; Shift+Tab удаляет один таб или до двух пробелов в начале каждой строки. Для одиночной каретки обработчик меняет отступ текущей строки.
- После изменения редактор отправляет input event, поэтому существующие обработчики черновиков сохраняют обновлённый текст.
- Ctrl/Meta+Enter вызывает кнопку действия, а не дублирует логику выполнения: у каждого редактора остаётся один путь запуска/проверки.
- Текст подсказки добавляется после поля, связывается через aria-describedby; aria-keyshortcuts описывает поддерживаемые клавиши.
- CSS увеличивает высоту редакторов на мобильных экранах и удерживает горизонтальную прокрутку внутри textarea.
- Реальная совместимость с экранной клавиатурой Android, TrebEdit и ТВ-пультом требует отдельной ручной проверки.


### Уточнение валидатора ID после A7

Статическая проверка теперь учитывает не только `id="..."` в HTML, но и строковые ID, назначаемые динамическим узлам через `.id = "..."` в JavaScript. Объединённый набор проверяется на дубликаты, после чего ссылки вида `$("#...")` сопоставляются с обоими источниками. Это устраняет ложное падение на навигации уроков A7 и сохраняет проверку отсутствующих ID.
